# Proposals: doppelganger

Written by loopers. Each proposal: what, why, links. Jody promotes accepted ones into ROADMAP.md (via an agent);
the looper then marks it `promoted` or `declined` here with the date.

## Open
- **Handlers take the tenant from the instance, not the token** (2026-10-28, #6): `callerIdentity` (internal/daemon/server.go) uses the caller token's namespace as the tenant. The tenant door also admits `/system` callers, whose namespace is not `/tenants/<tid>`, so their context or sessions would be keyed under `/system`. Since 2.5 the request's `tenant` (the route field, checked against the instance by the generated server) or the instance's own tenant says which tenant is meant; use that, and refuse or define what a `/system` caller may do.
- **tacplus: a route field marked `assert_required` breaks the generated MCP tests** (2026-10-28, #6): with `string tenant = N [(spec.assert_required) = true]` and `route_field: "tenant"`, the generated `doppelganger_mcp_test.go` passes `tenant` as a tool argument and dispatch refuses it ("tenant is set by the server from your session's tenant; it is not a tool argument"), so `go test ./tacplus/...` fails. Doppelganger leaves the field unasserted (the route field is already refused empty or malformed). Worth a tacplus bug, or `ValidateTenantRouting` refusing the combination.
- **Panel: rerun the backtests when a vendor's latest changes** (2026-10-31, #10): Jody asked that a new "latest" model be backtested before it is trusted. llmproxy's `ListModels` now reports each alias's current `provider_model` (tacplus-dev/llmproxy#13), and every panel answer records the model that gave it. Still open: where the backtest questions live (fixture files in this repo, or records), who runs them and under which identity (a rerun is a `GeneratePanelAnswer` by a tenant user and an `UpdatePanelDecision` under the person's entitlement), and how a recorded decision maps onto a run's merged options, which differ per run (by hand, or a moderator mapping checked by code). Then: poll `ListModels`, and on a change rerun each, so the track record shows the new model apart from its predecessor.
- **Panel: backtest fixtures** (2026-10-31, #10): the acceptance backtests (tacplus#212 as known on 2026-10-29 against tacplus#259's choice; `decisions/s2s-never-crosses-tenants-2026-10-31.md`; `decisions/rust-default-language-2026-10-27.md`) need their situations written down as known before each decision, without the decision itself (best assembled from the cited documents at their revision on that date, not rewritten by someone who knows the outcome), and a small client (or the planned local client) to run them. Worth doing with the live run.
- **Panel: who decides reversibility and security** (2026-10-31, #10): `reversible` and `touches_security_or_identity` are the caller's word (the honor system, like caller context). A panel-side check (any lens objecting on security grounds, or a question kind such as `security-design`) sending it to the person regardless would be safer; needs a decision.
- **Panel: cost bound** (2026-10-31, #10): a run is one phase-1 call per seat plus one per seat per lens (18 for three seats), plus three moderator calls, each up to three attempts. If cost matters, a per-run budget or fewer lenses per seat.
- **Platform item still names the GitLab context repo** (2026-11-02, #11): tacplus-dev/roadmap `items/doppelganger-fleet-service.md` says doppelganger needs "a current clone of `secondstar/jody`", pulled "through the gitlab-connector". The repo is now github.com/jodydadescott/jody; the item wants the GitHub repo and a reader that fits it (the GitHub App in this README's "Context repo access", or a connector for GitHub). A change in that repository, so not made here.
- **Context repo: protect `main` on the server** (2026-11-02, #11): GitHub Free gives a private repo no branch protection or rulesets, so `main` of jodydadescott/jody rests on doppelganger's own code and `nopush_test.go`. GitHub Pro (Jody's decision) would let `main` require a PR again, as on GitLab; then the README caveat can go.
- **looper-trace reads none of doppelganger's handlers** (2026-11-03, #12): `looper-trace check` reports 0 handlers here, because every downstream call is through a helper (`Engine`, `Panel`, the stores) or an injected field (`Server.Records`, `LlmProxy.Client`), never `...Clients()...XClient()` in the handler. The handlers forward `trace_id` through a context value (`internal/daemon/trace.go`) and `trace_test.go` covers each, but the check cannot confirm it. A looper change (tacplus-dev/looper), not made here: follow calls into same-package helpers, or recognise a context-carried trace_id.
- **Context from a Watch-fed cache** (2026-11-06, #7): every answer reads the tenant's and the user's context rows from stratum (two direct reads; a panel run one more). With the write surface, `WatchContextDocumentChanges` (snapshot, then the change feed, resumable by revision) could keep the instance's copy current and cut those reads. Nothing needs it today; worth it if answer latency or stratum load matters. The grant is in place (`s2s_subscribe` names doppelganger).
- **tacplus: a record written only through the write surface still needs a topic** (2026-11-06, #7): with no `event_publish`, a `(spec.record)` must still declare `s2s` (generation: "declares no producer surface") and the service must keep `eventbus` in `depends` (the synthesized `<T>Bus` topic's broker must resolve), though nothing publishes on it and stratum declares `no_bus_ingest`. A tacplus change (USER.md: "A record is still an event in 2.5"), so a record a no-bus store holds could drop both. Still so in 2.6.1 (#13: dropping `eventbus` fails with "EventBus topic doppelganger.ContextDocumentBus declares broker label \"eventbus\" but no matching broker service exists").

- **tacplus 2.6 warns on `(spec.deleted_flag)`** (2026-11-06, #13): on 2.6.1 `tacplus build` logs "Skipping unknown annotation - no validation template available" for `deleted_flag` on `ContextDocument`, `Session` and `PanelRun` `deleted` (twice each); 2.5 did not. The gates pass and nothing in 2.6.0's notes deprecates it. Worth asking tacplus whether this is a missing Go validation template (a tacplus bug) or a hint that the soft-delete marker moved; if it moved, follow it here.
- **Release: pin a launcher release, not a commit** (2026-11-13, #2): release.yml builds the launcher from source at `LAUNCHER_COMMIT`, as llmproxy's does, because tacplus-dev/launcher has no tag or GitHub release yet. Once it releases by version, pin that version (and its checksums) here and in the other services' release workflows, so a launcher fix reaches every image by one documented move.
- **Release: the workflow is shared by every service but copied** (2026-11-13, #2): llmproxy, deploymentproxy and doppelganger each carry their own release.yml and release-tags/notes scripts, already diverging (this one runs the gates in the pinned build image and can publish an existing tag). A reusable workflow in tacplus-dev/looper (as planning-files.yml is) would keep the line-tag and Latest rules in one place.
